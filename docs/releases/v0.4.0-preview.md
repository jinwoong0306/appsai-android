# v0.4.0-preview — 목업 로그인과 첫 실행 알림

## 구현

- 실행 진입점을 로그인 화면으로 변경했다. 버튼을 누르면 바로 홈으로 이동한다.
  실제 계정 인증·가입·비밀번호 입력은 없으며 목업임을 화면에 표시한다.
- 로그인 상태는 기기에 유지된다. 설정의 로그아웃으로 로그인 화면에 돌아가며
  친구·대화·코인 데이터는 지우지 않는다.
- 첫 실행에서 Android 13 이상 알림 권한을 요청한다. 허용하면 환영 알림을
  한 번만 발송한다. 거절해도 로그인할 수 있고, 설정에서 나중에 허용할 수 있다.
- 알림을 누르면 앱으로 이동한다. 서버 푸시·정기 알림·사용량 자동 감시는 추가하지 않았다.
- 최신 캐릭터 9종과 기존 꾸미기·상점을 유지하고 앱 아이콘을 추가했다.

## 빌드와 산출물

`./gradlew.bat :app:exportPreviewApk --offline`

산출물: `app/build/outputs/deliverables/Appsai-v0.4.0-preview-debug.apk`.
본체·계측·설치용 APK 빌드 성공. 기존 데이터를 유지하는 업데이트 설치를 진행했다.
로컬 Firebase 구성 및 App Check 토큰은 Git에 포함하지 않는다.

## AI 연결 진단

연결된 휴대폰의 설치 버전은 v0.3.1-images였다.
기존 APK에서 연결 진단을 실행해 Gemini 요청 이전의 App Check 단계 실패를 확인했다.
휴대폰 디버그 토큰 교환 실패 로그와, 콘솔에 에뮬레이터 토큰만 등록된 상태를 확인했다.
사용자 승인과 브라우저 제어 반환 후 `Appsai Galaxy S22 Ultra debug` 등록을
콘솔에서 확인했다. 중복 토큰은 추가하지 않았고 기존 에뮬레이터 등록도 보존했다.
가짜 AI 답변으로 대체하거나 App Check를 해제하지 않는다.
등록 후 첫 진단은 아직 인증 단계에서 실패했으나, 이후 실제 휴대폰 진단에서
`APP_CHECK_ACCEPTED`, `GEMINI_RESPONSE_RECEIVED`, `response_characters=34`를 확인했다.
개인정보 없는 합성 요청에 대한 실제 공급자 응답이며 기존 사용자 메시지를 재전송하지 않았다.
진단 러너에는 비밀 원문 대신 인증 재시도 제한·거부·HTTP 상태만 기록하도록 보완했다.

## 검증 범위

OnboardingFlowTest와 CustomizationFlowTest가 `OK (4 tests)`로 통과했다.
로그인 버튼·로그인 유지·알림 1회 발송·기존 꾸미기 저장 및 설정 진입을 포함한다.
테스트의 액티비티 감시자 재등록과 UI 생성 완료 동기화를 수정했다.
휴대폰에도 데이터 삭제 없이 업데이트 설치했고 로그인 화면 표시를 확인했다.
로그인 화면·시스템 알림 권한 요청·환영 알림 표시를 에뮬레이터에서 직접 확인했다.
기존 MainFlowTest는 API 37의 UiAutomation 중복 등록/연결 오류로 실패했고,
재부팅 후에도 재현됐다. 이를 제품 통과 결과로 표시하지 않는다.
의상 위치 정밀 검증 및 전체 기기·테마 매트릭스는 이번 범위에서 제외한다.
