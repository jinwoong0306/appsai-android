# v0.3.0 — 데모 코인 상점

## 구현

- 하단 상점에서 30개 소품을 부위별로 탐색하고 캐릭터를 바꿔 착용 미리보기를 본다.
- 최초 500 데모 코인과 기존 무료 8종을 제공한다. 가격은 얼굴 60,
  머리/목·몸 90, 손소품 120, 등 150 코인인 임시 값이다.
- 이미 장착한 소품은 이전 버전에서 잃지 않도록 최초 전환 때 보유 처리한다.
- 구매는 확인 후 진행하며 취소·중복 구매·잔액 부족 때 차감하지 않는다.
  차감, 보유 아이템, 구매 기록은 하나의 SQLite 트랜잭션으로 저장한다.
- 구매품은 꾸미기에서 장착할 수 있다. 미보유 소품은 상점으로 연결하며
  친구 생성·꾸미기 저장에서도 보유 여부를 확인한다.
- 현금 결제·환전·실제 활동 보상·일일 보상·서버 지갑은 없다.
  확정 경제 시스템이 아니라 로컬 구매 흐름 목업이다.

## 저장 및 기존 기능

DB 버전 5는 demo_wallet, owned_items, purchases를 추가한다.
초기 코인과 아이템을 앱 재실행마다 다시 지급하지 않는다.
기존 친구·외형·대화·경험치 및 Gemini 연결 코드는 보존한다.
로컬 Firebase 구성과 비밀 토큰은 저장소에 포함하지 않는다.

## 검사 방법

본체·계측 APK 빌드 성공. Pixel 7 API 37에서 아래 핵심 테스트가
`OK (19 tests)`로 통과했다. `-PfirebaseDisabled --offline` 공개 구성 빌드도 성공했다.
실제 상점 탭에서 데모 잔액, 부위 분류, 캐릭터 미리보기와 구매 확인창을 확인했다.

- ShopFlowTest: 실제 구매 화면의 미리보기·취소·확인·보유 상태.
- DemoShopStoreTest: 초기화 1회, 임시 가격, 중복·부족 잔액, 0잔액,
  잘못된 ID, 기존 장착품 보존, DB 제약, 실패 시 전체 롤백.
- CustomizationFlowTest: 30종 로딩, 5부위 저장·취소·다시 열기, 설정 이동.
- MainFlowTest 및 FriendsDatabaseMigrationTest: 기존 주요 흐름과 추가 마이그레이션.

실제 AI 요청은 이 상점 회귀의 검증 대상이 아니다. 네트워크 회귀는
명시적인 모의 응답을 사용하며 코인 UI 테스트는 사용자 지갑 대신
테스트 전용 메모리 SQLite로 실제 구매 트랜잭션을 실행한다.

첫 구매 UI 테스트는 임시 DB 정리 순서와 확인 버튼 콜백 완료 전 검증 때문에
실패했다. 목록의 임시 DB 참조를 해제한 뒤 닫고, UI 이벤트 큐 처리 후 검사하도록
수정했다. 에뮬레이터의 중복 UiAutomation 등록 오류는 데이터 초기화 없이
재부팅해 복구했으며 같은 APK의 전체 19건 통과를 확인했다.

## 별도 검증 항목

전체 기기/API·다크/큰 글꼴/가로·접근성·장기 데이터량은 별도로 검증한다.
기존 PACKAGE_USAGE_STATS lint 오류와 경고는 숨기지 않는다.
마지막 lint 결과는 해당 기존 오류 1건과 경고 13건이다.
이 버전은 핵심 검사 후 올리는 작업 버전이며 전체 검증 완료 표시는 아니다.
