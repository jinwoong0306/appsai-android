# 개발 로드맵과 팀 작업

## 우선 원칙

완성도와 실제 시연을 우선한다. 예시 대사·목업을 AI 작동이나 구현된 화면으로 설명하지 않는다. 날짜는 공지된 발표 외에는 확정하지 않는다.

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 0 현재 | MVP 이관과 구조·수업 가이드 정리 | 빌드 성공, 실제 상태와 제약 기록 |
| 1 화면 | 홈·앱 선택·채팅·설정을 XML과 Java로 분리 | 기존 친구 생성·저장·조회 회귀 통과 |
| 2 사용량 | 권한·선택 앱·기준 시간·자동 확인·알림 | 권한 거부/철회, 지연, 재시작, 중복 발송 검증 |
| 3 AI | 안전한 API 연결·캐릭터 대화·오류 재시도 | 키 미노출, 응답·오류 및 전송 정보 검증 |
| 4 목표·관계 | 사용자 확인 기반 기록, 누적 경험치, 기분 | 중복 방지·재시작 유지·쉬는 날 처리 |
| 5 꾸미기 | 도트 캐릭터와 소품·장착 저장 | 리소스 출처 확인, 복원·다양한 화면 확인 |
| 6 최종 | 실제 기기·예외 테스트, 시연·발표 | 전체 태스크, 팀원 기여, 기능·제약 증빙 |

기말 발표 전 우선순위는 실제 동작하는 핵심 흐름이다. 결제·랭킹은 구현하지 않은 장래 아이디어로 분리한다.

## 과제 발표

- 중간: 11월 3일·5일, 5~10분, 자료는 첫날 수업시간 전 제출. 실제 구성 화면, 전체 설계와 필수 기능, 진척과 남은 작업이 필요하다.
- 최종: 12월 1일·3일, 10~15분, 자료는 첫날 수업시간 전 제출. 기존 조사·차별성, 실제 동작 시연, 태스크·역할·일정을 포함한다.
- 후속 공지 및 실제 팀 발표 순서는 e-class에서 확인한다.

## 3인 팀 역할 예시（기능별 미배정）

최종 관리자: **@jinwoong0306**. 팀원: **@Creepc**, **@jaezero**. 팀원의 초대 수락 및 접근 상태는 GitHub에서 확인한다.

| 영역 | 실제 개발 작업 예시 |
|---|---|
| 화면·캐릭터 | XML 화면, 목록 어댑터, 도트 리소스 적용 |
| 사용량·알림 | 권한, 사용 통계, 백그라운드 작업과 알림 |
| 채팅·데이터 | SQLite 분리, 채팅 기능, AI 연동 및 오류 처리 |

역할은 상호 교차 리뷰하고 팀원 전원이 실제 Java/XML 개발에 참여한다. 실제 배정은 팀원과 협의한다.

## 협업 흐름

1. 이슈에 목표·완료 조건·담당자를 기록한다.
2. `feature/기능명`, `fix/문제명` 등 브랜치에서 관련 변경을 작업한다.
3. 기능 단위의 실제 변경을 각자 커밋하고 빌드·검증 결과를 기록한다.
4. 변경 내용과 검증을 팀원이 확인한 뒤 기본 브랜치에 반영한다.
5. 발표용 진행 현황과 팀원별 커밋 증빙을 실제 이력에서 준비한다.
