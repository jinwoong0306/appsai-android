# 앱사이 프로젝트 구조와 데이터 흐름

## 목표와 현재 상태

Java와 XML 기반 네이티브 Android 앱을 만든다. 현재 `MainActivity`가 화면, SQLite, 앱 목록과 사용량 조회를 함께 처리한다. 공통 화면 틀만 XML이며 나머지는 동적으로 생성한다. 아래 구조는 리팩터링 목표이며 아직 모두 존재하지 않는다. 기존 `kr.example.haliltalk` 패키지와 앱 ID는 데이터·설치 호환성을 위해 지금 변경하지 않는다.

## 목표 구조

```text
app/src/main/
├─ java/kr/example/haliltalk/
│  ├─ ui/            # 홈, 앱 선택, 성격 설정, 채팅, 설정 화면
│  ├─ data/          # SQLite 접근, 메시지·친구 저장
│  ├─ model/         # 친구, 메시지, 사용량 규칙, 목표 데이터
│  ├─ usage/         # 사용 정보 권한 확인, 선택 앱 사용 시간
│  ├─ notification/  # 규칙 확인, 알림 생성·중복 방지
│  ├─ ai/            # 대화 요청 인터페이스, 응답·오류 처리
│  └─ character/     # 성격, 관계 경험치와 표정·소품 규칙
├─ res/
│  ├─ layout/        # XML 화면과 목록 항목
│  ├─ drawable/      # 직접 제작 또는 라이선스 확인한 이미지
│  ├─ values/        # 색상·문구·치수·테마
│  ├─ menu/          # 필요한 경우 메뉴 XML
│  └─ mipmap/        # 앱 아이콘
└─ AndroidManifest.xml
```

필요한 시점에 폴더를 만들고 실제 클래스를 이동한다. 사전에 빈 패키지만 늘리지 않는다. `ai`는 제공자 교체가 가능하도록 화면과 분리하고 실제 연결 시 SDK·인증 방식을 확인한다.

## 기본 흐름

1. 사용자에게 표시 가능한 앱 목록을 제공하고 앱·성격 선택으로 친구와 채팅방을 저장한다.
2. 사용 정보 접근 권한이 있는 경우 선택한 앱의 사용 시간을 조회한다. 앱 사용 목적이나 시청 콘텐츠는 알 수 없다.
3. 향후 사용량 기준을 백그라운드에서 확인해 메시지를 만들고 알림을 보내되 지연과 중복·권한 철회를 처리한다.
4. 사용자가 자유 메시지를 보내면 최근 대화와 허용된 기억만 AI에 전달한다. 응답 실패를 표시하고 재시도한다.
5. AI가 목표 완료를 제안하면 사용자 확인 후 기록한다. 경험치·재화는 앱의 정해진 규칙으로 처리한다.

## 저장 구분

| 데이터 | 기본 보관 | 주의점 |
|---|---|---|
| 친구·성격 | 기기 SQLite | 앱 패키지와 사용자가 설정한 이름 구분 |
| 채팅·전송 상태 | 기기 SQLite | 삭제 가능, 클라우드 전달 범위 안내 |
| 사용량 규칙·알림 이력 | 기기 SQLite | 선택 앱만, 일자별 중복 방지 |
| 목표·완료 기록 | 기기 SQLite | 사용자 확인 후 반영 |
| 관계·아이템 | 기기 SQLite | 중복 적립 방지, 삭제·백업 정책 필요 |
| AI 키 | APK·Git에 저장 금지 | 안전한 연동 수단 확정 후 도입 |

계정 동기화, 서버 검증, 랭킹과 결제는 추후 설계한다. 지금의 로컬 저장만으로 유료 재화 보안이나 기기 간 동기화를 보장하지 않는다.

## 플랫폼 제약

- 실행 가능한 앱을 대상으로 하는 제한적 조회를 우선하며 모든 설치 패키지를 볼 수 있다고 가정하지 않는다. Google Play의 앱 가시성 정책과 사용자 설명을 출시 전 점검한다.
- 사용 정보 접근과 알림 권한은 별개다. 권한이 없을 때도 기본 채팅이 동작하도록 한다.
- 백그라운드 확인 시점은 시스템이 조정하므로 정확한 60분 시점의 알림을 보장하지 않는다.
- 키·대화·사용량은 민감하게 다루며 외부 모델을 사용할 때 전송 범위와 데이터 처리 조건을 확인한다.
