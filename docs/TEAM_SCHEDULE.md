# 앱사이 3인 팀 프로젝트 상세 일정계획표

**계획 기간: 2026.09.08~2026.12.03 / 작성 기준: 2026.11.02**

> **11월 3일은 개발을 시작하는 날이 아니라, 실제 설치·실행·시연 가능한 1차 완성본을 내는 날이다.**
> 11월 5일 발표 가능성에 기대어 개발 마감을 미루지 않는다. 12월 1일에 최종 제출 준비를 끝내고, 12월 3일은 배정 시 발표와 질의응답에 사용한다.

## 1. 계획의 기준과 읽는 방법

| 구분 | 이 계획에 적용한 기준 |
|---|---|
| 프로젝트 | 앱사이(AppSai): 설치 앱을 친구로 등록하고 대화하며 사용 습관을 확인하는 Android 앱 |
| 기술 | Android Studio, Java, XML, SQLite. 웹·하이브리드 앱으로 대체하지 않음 |

| 최종 마감 | **11/29 최종 후보본 → 11/30 자료·리허설 완료 → 12/01 첫 수업시간 전 제출** |

### 11월 3일에 무엇을 완성하는가

이 계획의 **1차 완성본**은 화면 목업이나 코드 일부가 아니라, 사용자가 처음부터 끝까지 사용할 수 있는 아래 핵심 범위다.

**첫 실행 안내 → 앱 검색·선택 → 성격 선택·친구 추가 → 대화 전송과 로컬 예시 답장 → 동의한 선택 앱의 수동 사용량 확인 → 앱 재실행 후 친구·대화 복원.**

현재 미구현인 AI 자유 대화·자동 알림·도트 꾸미기까지 11/03 완료했다고 간주하지 않는다. AI 응답은 예시 답장과 구분한다. 이 확장 기능은 11월의 선택적 개선 슬롯에만 배치하며, 핵심 개발 마감이나 최종 필수 범위를 늘리는 근거로 사용하지 않는다.

교재 파일 처리 기능은 현재 미구현이다. 11/02에 최소 내보내기를 시도하되 핵심 시연본을 깨뜨리지 않으며, 미완료 시 11/03 발표에서 남은 필수 보완으로 명시하고 11/12까지 검증한다. 따라서 **11/03 1차 완성과 수업 요건 전체 충족은 별도 확인 항목**이다.

## 3. 3인 역할 분담표

| 역할 | 주 개발 영역 | 11/03까지 책임 산출물 | 이후 보완 영역 | 교차 검토 |
|---|---|---|---|---|
| **A / 진웅: 통합·대화·데이터** | Java 대화 처리, SQLite 저장·복원, 공통 연결 코드, 최종 통합 | 메시지 전송·예시 답장, 친구·대화 복원, 설치 가능한 통합 APK | 파일 내보내기/가져오기, 저장 예외·마이그레이션, 선택 시 AI 연결 | C가 저장·대화 결과 검토 |
| **B / 팀원 2: 화면·사용성** | XML 화면, 앱 선택·검색 UI, 친구·채팅 표시, 안내 문구 | 안내·홈·앱 선택·채팅 화면 연결, 빈 화면·검색 결과 없음 처리 | 남은 동적 UI의 XML 전환, 가독성·화면 크기, 선택 시 기본 캐릭터 | A가 화면 연결·데이터 표시 검토 |

팀의 실제 발표가 11/05 또는 12/03이어도 제출·완성 기준을 뒤로 미루지 않는다. APK·영상의 실제 제출 필요 여부와 파일 형식은 e-class 공지로 확인하고, 이 계획에서는 팀 내부 준비물로 확보한다.

## 12. 발표 자료에 바로 넣을 요약 문안

> 본 프로젝트는 3인 기능 분담으로 진행하며, 9월 팀 구성과 제안 발표를 거쳐 화면·대화/저장·사용량/권한 영역을 병렬 개발하는 일정으로 계획하였다. 11월 3일 중간 발표까지 친구 추가, 로컬 대화, 선택 앱의 수동 사용량 확인, 데이터 저장·복원을 연결한 실행 가능한 1차 완성본을 확보하는 것을 목표로 한다. 이후에는 중간 피드백과 남은 필수 요건을 11월 12일까지 보완하고, 선택 개선은 11월 19일에 마감한다. 11월 26일까지 통합 검증을 마친 뒤 11월 29일 최종 후보본, 11월 30일 발표 준비를 완료하고 12월 1일 첫 수업시간 전 제출한다. 12월 3일 발표 배정에도 같은 준비 마감을 적용한다.

발표에서는 이 문안의 “목표”를 실제 검증 없이 “완료”로 바꾸지 않는다. 9~10월 상세 계획은 실제 작업 이력과 대조하여 사용한다.
